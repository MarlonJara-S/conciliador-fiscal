| Date | What I learned | What I still don't understand | Interview question I could answer now |

| 2026-10-03 | A Git branch is just a file in .git/refs/heads holding a commit hash; only the checked-out branch (HEAD) moves forward on a new commit. Use main as the default branch, one short-lived branch per change (GitHub Flow), and Conventional Commits in English. A commit is a full snapshot, so a leaked secret stays in history: revoke it first. | How merges and Pull Requests join two branches. | "What is a Git branch internally, and what happens to it when you commit?" |
| 2026-10-03 | PATH is an ordered list of folders the OS searches for a command; the first match wins. Activating a .venv just puts .venv/Scripts at the front of PATH, so its python and pip win over the global ones (`where python` / `which python` show the search order). | How the activate script modifies PATH, and what `deactivate` restores. | "What does activating a virtual environment actually do?" |
| 2026-10-03 | Transitive dependencies (the dependencies of my dependencies) are pinned too: if they were left free, a new release of one of them could break the project without any change on my side. pip-compile pins everything and records why each package is there (`# via`); pip-sync makes the environment match the lock files exactly. | When and how to safely upgrade pinned versions. | "Why do you pin transitive dependencies, not just direct ones?" |
| 2026-10-03 | pytest and Pylance find packages independently: pytest uses `pythonpath = ["src"]` from pyproject.toml, while Pylance (the VS Code editor) needs its own settings (selected .venv interpreter and `python.analysis.extraPaths`). `src` is a folder on the search path, not a package, so imports start at `conciliador_fiscal`. | Whether installing the project in editable mode (`pip install -e .`) would replace both settings. | "Why use a src layout, and how do tests import the package?" |
| 2026-10-14 | XXE (XML eXternal Entity): an XML file can declare an entity whose value comes from a file or URL (`<!ENTITY x SYSTEM "file:///...">`); a parser that resolves it leaks local files (or makes internal requests, SSRF). In a lab, `XMLParser(resolve_entities=True)` printed my secret file as the supplier name; with `resolve_entities=False, no_network=True, load_dtd=False` the value came back empty. lxml 6 already blocks external entities by default, but options are written explicitly so the intent is visible and survives default changes. Real DIAN invoices never carry a DOCTYPE, so the parser should reject any document that has one. | How the "billion laughs" expansion is limited by libxml2 and `huge_tree=False`. | "What is an XXE attack and how do you parse untrusted XML safely in Python?" |
| 2026-10-14 | Namespaced XML needs a prefix→URI map for every lookup; `find` returns an element or None (mypy-friendly), `xpath` returns a list of anything. DIAN invoices are parsed in two layers: the envelope, then the embedded Invoice text, both with the same safe parser. | When `xpath` is worth it over `find`/`findall`. | "How do you read namespaced XML with lxml?" |
| 2026-10-14 | A parser for third-party documents maps every failure (malformed XML, missing element, broken domain rule) to one domain error with the failing path, so the document goes to quarantine and processing continues. Real data drove model changes (per-unit taxes without a rate). | How to report several errors of one document at once instead of stopping at the first. | "How do you handle errors when processing third-party documents?" |
